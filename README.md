# FrameLink

Камера iPhone в OBS Studio через локальную сеть. Safari захватывает изображение, OBS Browser Source принимает его по WebRTC. Компьютер может подключаться к роутеру по Ethernet. Для работы готового приложения достаточно Windows x64, браузера, локальной сети и OBS с Browser Source. Интерфейсы, QR-код и mkcert встроены в EXE.

## Первый запуск

1. Запустите `dist\FrameLink.exe`. Для переноса на другой ПК достаточно этого файла. Панель откроется в браузере по адресу `http://127.0.0.1:8765/dashboard`. Двойной щелчок по значку в трее снова открывает панель. Правый щелчок даёт команду выхода. В консоли доступно Ctrl+C.
2. Дождитесь QR-кода. FrameLink выбирает активный IPv4 домашней сети и выпускает сертификат для него, имени ПК, localhost и loopback. Первый запуск создаёт собственный центр сертификации в профиле текущего пользователя.
3. Настройте доверие **на iPhone** по инструкции ниже. На Windows панель и OBS используют loopback, поэтому установка корневого сертификата в Windows для них не требуется.
4. Подключите iPhone к Wi-Fi этой сети, отсканируйте QR-код и откройте ссылку в Safari. Выберите профиль **Основной** и нажмите **Начать трансляцию**. Подтвердите доступ к камере. Микрофон по умолчанию выключен.
5. В панели нажмите **Копировать ссылку OBS**. В OBS откройте **Источники → + → Браузер**, оставьте «Локальный файл» выключенным и вставьте ссылку целиком. Для основного режима укажите ширину **1920**, высоту **1080** и **30 FPS**. Для звука включите микрофон в FrameLink и при необходимости «Управлять звуком через OBS» в свойствах источника.
6. Включите **Предпросмотр**, чтобы проверить кадр на ПК. Затем его можно выключить или закрыть панель. OBS продолжит получать видео. Камеру удобно переключать и останавливать с телефона.

Адреса в полях панели показаны без секретной части. Кнопки копирования включают её. Камера и OBS могут открываться в любом порядке. Один экземпляр FrameLink обслуживает одну камеру, один активный Browser Source и одну управляющую вкладку. В разных сценах OBS добавляйте существующий источник.

## Доверие к локальному HTTPS на iPhone

FrameLink создаёт, но не устанавливает сертификаты в хранилища доверия. Вы сами принимаете решение о доверии на устройстве. Go, mkcert и Node.js на iPhone не нужны.

1. Найдите **`%LOCALAPPDATA%\FrameLink\FrameLink-CA.cer`**. Панель показывает полный путь в разделе «Первое подключение и сертификат». Это публичный корневой сертификат в формате DER.
2. Передайте **только этот файл** по доверенному каналу, например через личный USB-накопитель, совместимый с iPhone, и приложение «Файлы». Сверить SHA-256 файла на ПК можно командой ниже. Частный ключ центра `ca\rootCA-key.pem` позволяет выпускать доверенные сертификаты. Держите его в личном профиле Windows.
3. Откройте сертификат на iPhone. Если вы согласны на установку, откройте «Настройки → Профиль загружен» или «Основные → VPN и управление устройством», проверьте профиль и нажмите «Установить».
4. В «Настройки → Основные → Об этом устройстве → Доверие сертификатам» включите полное доверие установленному корню. Названия пунктов зависят от языка и версии iOS.
5. Откройте камеру по QR-коду. Safari должен открыть страницу без предупреждений о сертификате. Разрешите локальную сеть, если iOS покажет соответствующий запрос. При предупреждении проверьте доверие, дату и адрес из свежего QR-кода.

```powershell
Get-FileHash "$env:LOCALAPPDATA\FrameLink\FrameLink-CA.cer" -Algorithm SHA256
```

После завершения использования удалить доверие можно через настройки профилей iOS. Если вы сознательно удалите каталог центра на ПК, потребуется установить новый публичный корень на iPhone. Официальные инструкции по ручному доверию и мобильным устройствам. [Apple](https://support.apple.com/en-us/102390) · [mkcert](https://github.com/FiloSottile/mkcert#mobile-devices)

## Режимы и управление

| Профиль | Запрос захвата | Верхняя граница видеобитрейта для OBS |
| --- | --- | --- |
| Экономичный | 720p × 30 FPS | 3 Мбит/с |
| Основной | 1080p × 30 FPS | 6 Мбит/с |
| Движение | 1080p × 60 FPS | 10 Мбит/с |

Вручную доступны 480p, 720p и 1080p, 24/30/60 FPS и 1–30 Мбит/с. Safari согласовывает реальный режим с камерой. Браузер и сеть могут понизить разрешение и скорость. Значения в статистике позволяют проверить результат. Для режима 60 FPS также установите соответствующую частоту в Browser Source и настройках видео OBS.

- **Камера.** Передний и задний модули выбираются через `facingMode`. После разрешения доступа список объективов появится, если браузер перечислил несколько видеоустройств. Зум, доступные режимы фокусировки, экспозиции и экспокоррекция появляются по `getCapabilities()`. Доступность физических объективов определяет Safari. При смене устройства или формата возможен короткий разрыв.
- **Поворот и зеркало.** Применяются при отображении на телефоне и обоих приёмниках. Для вертикального кадра выберите соответствующий размер источника OBS. Масштабирование сохраняет пропорции.
- **Предпросмотр.** По умолчанию выключен. При включении камера открывает второй PeerConnection с тем же захватом и запрашивает для него до 360p по короткой стороне, 15 FPS и 1,2 Мбит/с. Возможности отправителя определяют применение ограничений. Отключение закрывает соединение и освобождает приёмник панели.
- **Управление с ПК.** После подключения доступны настройки качества, камеры, микрофона и ориентации. Первый запуск захвата подтвердите на самом iPhone. Повторный старт и остановка доступны из панели до перезагрузки мобильной страницы.
- **Сохранение.** Основные параметры, выбранный объектив и подтверждённые аппаратные настройки сохраняются в localStorage камеры. Аппаратные значения привязаны к устройству и заново проверяются по его возможностям. Предпочтение предпросмотра хранится в браузере ПК. У каждого адреса камеры своё хранилище. Токен OBS сохраняется в профиле пользователя ПК. Токен камеры меняется при каждом запуске сервера.
- **Фон и экран.** Во время работы держите Safari открытым и iPhone разблокированным. Страница запрашивает Screen Wake Lock при поддержке. После блокировки, звонка или выгрузки страницы iOS может прервать захват. Вернитесь в Safari и при необходимости нажмите кнопку запуска. При разрыве сигнализации страница повторяет подключение, сохраняя ещё активный трек.

## Сеть и диагностика

| Наблюдение | Что проверить |
| --- | --- |
| QR долго не появляется | Посмотрите сообщение LAN в панели и вывод консоли. Активному адаптеру нужен IPv4. При нескольких адаптерах задайте домашний адрес явно. |
| Safari не открывает страницу | Сравните адрес в QR с IPv4 Ethernet/Wi-Fi ПК. Проверьте доступ iPhone к ПК, гостевую изоляцию Wi-Fi, VPN, профиль сети и входящий TCP-порт HTTPS. |
| Страница видна, кадра в OBS нет | Должны быть активны камера и Browser Source. Проверьте полный URL с токеном, права Safari на камеру, доступ к локальной сети и прохождение ICE/UDP между iPhone и процессом браузера OBS. Изоляция клиентов на роутере может препятствовать прямому соединению. |
| Открылась вторая камера или панель | Закройте предыдущую вкладку с этой ролью. После необнаруженного обрыва освобождение роли может занять до очередной проверки связи. |
| Изменился IP ПК | Раз в 10 с сервер пересматривает выбор интерфейса. При смене адреса выпускает новый сертификат тем же корнем и обновляет QR в панели. Снова отсканируйте QR. Адрес OBS на loopback сохраняется. Если указан `-ip`, измените параметр при следующем запуске. |
| После перезапуска ПК Safari не подключается | Откройте новый QR из панели. Уже добавленный источник OBS переподключится по сохранённой ссылке. |
| В OBS скрыта сцена | Опция «Отключать источник, когда он не виден» выгружает страницу и освободит соединение. После показа источник подключится снова. |
| Высокая нагрузка | Закройте предпросмотр или всю панель. Проверьте экономичный профиль и фактические параметры OBS. |

Программа привязывает LAN HTTPS к выбранному адресу и не меняет Firewall, Defender или сетевой профиль. Если Windows предлагает разрешить входящие соединения, решение принимает владелец ПК. Для работы в домашней сети потребуется разрешённый доступ на выбранном частном интерфейсе. Передача медиа использует динамические ICE-порты браузеров. Для обычной LAN не нужны внешний STUN/TURN, маршрутизация через интернет или проброс портов роутера.

```powershell
.\dist\FrameLink.exe -ip 192.168.1.20
.\dist\FrameLink.exe -port 8443 -local-port 8765 -no-browser
.\dist\FrameLink.exe -help
```

Подставьте реальный адрес компьютера. Параметры `-no-tray` и `-data <путь>` отключают значок трея и выбирают каталог данных соответственно. Для каталога данных используйте личную папку, доступную только доверенным пользователям. Перевыпуск токена OBS выполняется после остановки приложения удалением файла `obs-token`. Затем заново скопируйте ссылку в OBS.

## Метрики

Каждые две секунды активный приёмник читает `RTCPeerConnection.getStats()`. Панель показывает метрики OBS в приоритете, затем метрики предпросмотра. Источник измерения подписан. При отсутствии свежего отчёта поле показывает прочерк.

- FPS берётся из `framesPerSecond` или из изменения `framesDecoded` за интервал. Разрешение берётся из inbound RTP или размеров декодированного видео.
- Битрейт вычисляется по изменению `bytesReceived` видеопотока. Для простого кадра фактический битрейт может быть существенно ниже заданного предела.
- RTT показывает круговое сетевое время выбранной ICE-пары. Для измерения полной задержки от объектива до экрана снимите общий миллисекундный таймер и вывод OBS второй камерой и сравните кадры.
- Потеря пакетов вычисляется по приращениям счётчиков lost и received за тот же интервал. Для отсутствующих полей или пустого интервала панель оставляет прочерк.

## Разработка и сборка

PowerShell и Git нужны для работы с исходниками. При первом запуске setup требуется интернет. Скрипт загружает переносимый Go с официального адреса и сверяет SHA-256. Исходники mkcert берутся из модуля разработчика. Его граф зависимостей закреплён в `tools/mkcert/go.mod` и `go.sum`. Скрипт проверяет Go-модули, собирает mkcert и сверяет хеш результата перед встраиванием.

```powershell
.\setup.ps1
.\build.ps1
.\run.ps1
```

Сборка вызывает `go vet ./...`, `go test ./...` и создаёт `dist\FrameLink.exe` (`windows/amd64`, CGO выключен). Переформатировать Go можно командой `.\.tools\go\bin\go.exe fmt ./...`. Кэши Go и файлы в `.tools` нужны только разработчику. После первой подготовки исходники можно собирать из локального кэша. Готовый EXE выпускает сертификаты и обслуживает страницы автономно.
