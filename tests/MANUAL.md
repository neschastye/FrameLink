# Проверка FrameLink

## Автоматические проверки на Windows x64

Сначала выполните `setup.ps1` и `build.ps1` в корне проекта. Обычный `go test` проверяет изоляцию маршрутов, обязательный Origin, токены ролей, формат сообщений, управление подписками и смену сертификата. Тест сертификатов использует временный центр, доверенный только проверяющему коду через локальный `CertPool`. Установка в Windows или iOS отсутствует.

Сквозной тест запускается по явному выбору, так как ему нужен браузер и собранный EXE. Путь к Chrome должен указывать на существующий браузер Chromium. Путь к OBS указывает на **каталог установки**, в котором есть `bin\64bit\obs64.exe`. При отсутствии переменной OBS роль приёмника выполняет третий тестовый браузер.

```powershell
$env:FRAMELINK_TEST_CHROME = 'C:\Program Files (x86)\Google\Chrome\Application\chrome.exe'
$env:FRAMELINK_TEST_OBS = 'D:\Steam\steamapps\common\OBS Studio'
$env:FRAMELINK_MEASURE_SECONDS = '30'
$env:FRAMELINK_SOAK_SECONDS = '300'
.\.tools\go\bin\go.exe test -run '^TestBrowserPipeline$' -count=1 -v -timeout 10m .
```

На другой установке подставьте свои пути. Для браузерного варианта уберите переменную OBS из текущего процесса. Параметры измерений и длительного прогона необязательны. Для многочасового прогона увеличьте также `-timeout`. Очистите переменные `FRAMELINK_TEST_*` перед обычной сборкой.

Тест создаёт временные каталоги, профили браузеров, тестовую сцену и отдельную переносимую копию OBS. Камера эмулируется внутри Chromium. HTTP loopback служит защищённым контекстом тестовой вкладки. Тестовый мост проверяет сертификат HTTPS/WSS реального FrameLink через временный корень и пересылает запросы на loopback. Приложение для iPhone использует HTTPS напрямую. Тест читает статистику декодирования приёмника через обычную панель. Он проверяет параллельный предпросмотр, его отключение, изменение качества, остановку, повторный старт, обновление вкладки и восстановление после разрыва сокета камеры. В браузерном варианте дополнительно проверяются аудиотрек, поворот и зеркало.

## Приёмка на физическом iPhone

Запишите модель телефона, версию iOS, используемый объектив, версию OBS, тип Wi-Fi, способ подключения ПК и параметры Browser Source. Согласие владельца требуется для установки доверенного профиля или изменения системных сетевых правил.

| Сценарий | Действия | Критерий |
| --- | --- | --- |
| Первое подключение | Установить публичный корень по README, отсканировать QR, разрешить камеру только по запросу Safari | Адрес HTTPS открывается без предупреждения. На телефоне появляется движущийся кадр |
| Базовая передача | Добавить ссылку как Browser Source, начать трансляцию в профиле «Основной», направить телефон на часы | В сцене движутся стрелки или показания таймера. Панель показывает источник статистики OBS, фактические размеры, FPS и битрейт |
| Управление | Проверить 480p, 720p, 1080p и 24/30/60 FPS, изменить битрейт, переключить камеры. При доступности изменить объектив, зум, фокус и экспозицию | Записываются фактические режимы устройства и значения после стабилизации. Кадр восстанавливается после смены формата |
| Геометрия | Снять асимметричную надпись, проверить 0/90/180/270° и зеркало в портретной и альбомной ориентациях | Направление и пропорции совпадают в OBS и предпросмотрах |
| Предпросмотр и звук | Включить предпросмотр параллельно с OBS, затем выключить и закрыть панель. Включить микрофон и произнести фразу | OBS продолжает получать кадры, его микшер реагирует на звук. Возврат в панель восстанавливает статистику |
| Потеря связи | Отключить Wi-Fi на 10–20 секунд и вернуть ту же сеть. Отдельно скрыть Browser Source с опцией выгрузки и снова показать | При активной вкладке и живом треке соединение восстанавливается. При завершении захвата Safari показывает возможность повторного старта |
| Блокировка и фон | Заблокировать iPhone, вернуться в Safari, переключиться в другое приложение и обратно | Зафиксировать поведение данной модели и iOS. После разрешённого повторного старта кадры снова поступают |
| Смена IP | На уже доступном втором адаптере или после естественного изменения DHCP проверить новый QR. Ручные изменения сети выполняет владелец | Новый адрес появляется в панели. Сертификат подходит к новому IP, корень прежний, OBS использует прежний URL |
| Автономность | Сохранить LAN с выключенным внешним интернетом по выбору владельца. Перезапустить EXE, подключить камеру по новому QR | Камера, QR, управление, статистика и OBS работают внутри LAN |
| Длительная работа и игра | 60–120 минут вести сцену с движением, сначала с выключенным монитором. Повторить с игрой и обычной записью OBS, сравнить с базовой сценой без камеры | Зафиксировать обрывы и восстановление, FPS, потери, память, загрузку и пропуски кадров OBS, температуру и питание телефона |

## Измерение производительности

Для сравнения возьмите периоды одинаковой длительности и сцену с одинаковым движением. Проверьте режимы с закрытой панелью, с панелью без предпросмотра и с включённым предпросмотром. Учитывайте прогрев кодека. Измерять полную задержку можно съёмкой одного физического события и монитора в одном высокоскоростном кадре. RTT доступен отдельно в панели.

`measure.ps1` принимает PID сервера, корневой PID отдельного браузера панели и PID OBS. Скрипт снимает working set в конце интервала. Для сервера он берёт собственный процесс, для браузера и OBS суммирует процессы их деревьев. CPU вычисляется по приросту процессорного времени процессов, существовавших в обоих снимках, и нормализуется на число логических процессоров. Общие страницы памяти при суммировании процессов могут учитываться несколько раз. Для измерения панели выделите отдельный профиль браузера без других вкладок. Значения OBS включают само приложение, его сцену и дочерний CEF.

```powershell
.\tests\measure.ps1 -ServerId 1000 -DashboardId 2000 -ObsId 3000 -Seconds 60
```

Подставьте фактические PID. Для GPU и пропусков рендеринга/кодирования используйте диспетчер задач Windows и окно «Статистика» в OBS. Измерения на эмуляторе не характеризуют энергопотребление, нагрев и задержку iPhone.
