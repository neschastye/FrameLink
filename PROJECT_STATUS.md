# FrameLink · состояние проекта

## Выпуск для Windows x64

Готовый файл — `dist/FrameLink.exe`, 12 903 936 байт. SHA-256 выпуска — `232FB3D8F697D238E045BAAC795244524527E62150D93917C8DB8A185AEBB52E`. Сборка выполнена на Windows x64 с Go 1.27.4, `CGO_ENABLED=0` и `-trimpath`. Проверен запуск EXE с чистым каталогом данных. Рабочие страницы, стили, скрипты, логотип, тексты лицензий, QR-генератор и утилита выпуска сертификатов поставляются внутри приложения.

**OBS Studio 33.0.1 принял видео синтетической камеры Chromium через WebRTC в настоящем Browser Source.** Для окончательной приёмки нужен физический iPhone с доверенным корнем и домашняя сеть пользователя. Порядок действий — в `README.md` и `tests/MANUAL.md`.

## Архитектура и реализация

- `main.go`, `network.go` — выбор интерфейса, контроль смены IPv4, генерация CA/сертификата, отдельные HTTPS LAN и HTTP loopback. mkcert запускается только при выдаче или перевыпуске. Временный исполняемый файл удаляется по завершении. Установка доверия в ОС, повышение привилегий и изменение правил Firewall отсутствуют в коде.
- `server.go`, `hub.go` — встроенные ресурсы, QR, сессионные токены, сигнализация с проверкой ролей, типов и размеров. Камера доступна по LAN. Панель, API выдачи ссылок и OBS доступны через loopback. Формирование ссылки авторизует устройство на роль. Секрет камеры и ключ панели обновляются при старте. Сохранённый токен OBS позволяет повторно использовать источник после перезапуска.
- `web/camera.js`, `web/rtc.js` — MediaDevices и один захват камеры. У каждого получателя свой PeerConnection. Источник собирает локальные ICE-кандидаты перед отправкой SDP. Внешних ICE-серверов нет. Камера поддерживает настройки качества, выбор доступных объективов, микрофон и аппаратные настройки при наличии соответствующих API.
- `web/viewer.js`, `web/dashboard.js`, `web/obs.js` — декодирование и статистика на приёмнике. На странице OBS только элемент video. Активный предпросмотр получает отдельную облегчённую видеодорожку из общего захвата, без звука. При отключении соединение закрывается. В режиме с одним OBS сервер обрабатывает сигнальные сообщения и небольшие отчёты getStats.
- `tray_windows.go` — значок в области уведомлений, открытие панели и выход через штатный Win32 API. `setup.ps1`, `build.ps1`, `run.ps1` отвечают за подготовку, выпуск и разработку. Основной модуль зависит от двух Go-библиотек. Зависимости mkcert изолированы в `tools/mkcert`.

## Нагрузка итоговой сборки

Ryzen 5 5600, RTX 5060, 16 ГБ, 12 логических процессоров. Профиль источника — 1080p30. Камера Chrome и OBS находились на том же ПК, панель была открыта, предпросмотр выключен. OBS работал с одной тестовой сценой. Игра, запись и вещание на внешний сервис в этот замер не входили.

| Компонент | Working set в конце 30 с, МиБ | Средняя доля CPU всего ПК |
| --- | ---: | ---: |
| FrameLink.exe, один PID | 21,0 | 0,02% |
| Отдельный Chromium панели со всеми процессами | 487,5 | 0,18% |
| OBS Studio с дочерними процессами | 524,8 | 0,59% |

На границах интервала OBS сообщал о приёме 1920×1080 и 30 FPS. Видеобитрейт составлял 1,19 и 1,37 Мбит/с. Для локального синтетического потока RTT и потеря пакетов отобразились как нулевые. Это измерения декодера на loopback. Полная задержка «объектив → экран», скорость на домашнем Wi-Fi и накладные расходы добавления источника в игровую сцену требуют отдельных замеров. Числа для Chromium и OBS включают базовую память приложений. Первая диагностическая серия учитывала всё дерево сервера и показала 56,1 МиБ, поэтому в итоговом сравнении сервер измерялся строго по PID.

## Аудит и зависимости

`govulncheck v1.10.0` при проверке официального готового mkcert v1.4.4 сообщил о 32 известных уязвимостях Go 1.18 в найденных символах. Для выпуска mkcert пересобран из модуля разработчика с Go 1.27.4 и закреплёнными версиями библиотек. Повторная сборка дала тот же SHA-256, записанный в `bundle/mkcert.sha256`. На момент проверки govulncheck сообщил `No vulnerabilities found` для итоговых бинарников FrameLink и mkcert. Оба графа Go-модулей прошли `go mod verify`.

Проверка кода охватила границу LAN/loopback, ограничение HTTP Host и WS Origin, выдачу и применение ключей ролей, срок жизни разрешений, лимиты чтения и очередей, обработку переподключений и размещение приватных файлов. Весь медиаобмен идёт через WebRTC. По WebSocket передаются SDP, состояние, команды и метрики. Приватные ключи остаются в каталоге данных пользователя. Архив исходников формируется из файлов Git.

## Следующая физическая проверка

1. С разрешения владельца установить публичный корень на iPhone и подтвердить открытие Safari без предупреждения. Измерить 1080p30 и доступность 1080p60 на конкретной модели.
2. Проверить переключение передней/задней камеры, доступные физические объективы, настройки фокуса и экспозиции, аудиосинхронизацию и поворот в обеих ориентациях.
3. Выполнить длительный прогон с игрой и обычной сценой OBS. Зафиксировать нагрев телефона, потери, пробуждение после блокировки, поведение при смене DHCP и фактическую сквозную задержку.

Порядок ручной приёмки и команды воспроизведения автоматических тестов находятся в `tests/MANUAL.md`. Для продолжения разработки начните с `setup.ps1`, затем `build.ps1`.
